# Limitations and Disclaimers

The NeuroQuant system is built as a robust end-to-end framework for machine learning and quantitative trading research. However, it is fundamentally an **educational paper-trading system** and is **not intended for real investment advice**. 

Please read and understand the following limitations before deploying or relying on this system.

## 1. Data Delays and Provider Limits
- **Data Latency**: Without a paid, premium broker API key (such as a direct NSE/BSE FIX connection), the market data provided via Yahoo Finance (`yfinance`) is typically delayed by **15 to 20 minutes**. Live, real-time tick data requires commercial data subscriptions.
- **Rate Limits**: Free tiers of public APIs (Google News RSS, Yahoo Finance, etc.) are subject to rate limiting and may temporarily block requests if queried too aggressively. The system includes exponential backoff logic, but this does not bypass fundamental provider limits.

## 2. Probabilistic Predictions
- **No Guarantees**: All predictions generated by the Machine Learning (XGBoost, LightGBM, TFT) models are strictly **probabilistic**. They forecast the *likelihood* of directional movement based on historical statistical patterns, not certainties.
- **Regime Shifts**: Financial markets are highly non-stationary. A model that performs exceptionally well during a sustained bull market regime may degrade rapidly during a sudden crisis or sideways regime. The included Hidden Markov Model (HMM) attempts to detect these shifts, but it acts as a lagging indicator.

## 3. Honest Accuracy Standards
- **Realistic Accuracy**: In quantitative finance, predicting the daily directional movement of an asset is notoriously difficult. A realistic out-of-sample directional accuracy for daily data (D1) sits within the **52%–62%** band. 
- **The "75% Rule"**: This repository strictly enforces the "Honesty Law." If any model claims >75% directional accuracy in walk-forward cross-validation, it is almost certainly suffering from **look-ahead bias** (data leakage) or overfitting. The backend pipelines are designed to aggressively flag and reject models that exhibit impossible accuracy.

## 4. Execution and Cost Slippage
- **Paper Trading Only**: The internal portfolio engine executes trades theoretically. Real-world execution involves bid/ask spread slippage, partial fills, liquidity constraints, and varying broker fees. 
- **Cost-Adjusted Sharpe**: While the `ModelMonitor` reports a `cost_adjusted_sharpe` metric (assuming standard brokerage and STT fees), real slippage often exceeds static baseline costs during periods of high volatility.

## 5. System Scope
- The system is an advanced boilerplate for research, demonstrating how to construct leak-proof feature pipelines, handle walk-forward ML training loops, and integrate real-time inference onto a modern React frontend.
- It is **not** a "get rich quick" black box. Any deployment with real capital requires an independent, rigorous audit of the code, infrastructure, and strategies.
